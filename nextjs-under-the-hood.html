Section 13

    
Cache System

    
Remember answers so you don’t ask the library the same question every second.

    
🐘Like an elephant’s memory: First visit = slow (cache miss, go to database). Second visit = fast (cache hit, use saved answer).

    

    
    

      
Route Cache
Remembers whole pages that don’t change often

      
Fetch Cache
Don’t ask the same API twice in one cook session

      
Image Cache
Keeps resized photos ready nearby

      
ISR Cache
Old page stays fast while a fresh one bakes behind the scenes

    

    
    

      
Remember from this chapter

      
    
        
  • Caching is a tradeoff: speed vs freshness — configure revalidate and fetch options on purpose.
    • 
        
  • “Stale data” bugs often mean cache rules, not React bugs.

Bonus 1

    
Middleware

    
Code that runs before a page, for matching URLs only.

    
🚪Like a bouncer: Before anyone enters a room, the bouncer checks a list. Wrong door? Send them elsewhere (redirect). Old sign? Quietly show the new room (rewrite). All good? Let them in (next).

    
export function middleware(req) {
  if (!req.cookies.has('session') && req.nextUrl.pathname.startsWith('/dashboard'))
    return NextResponse.redirect(new URL('/login', req.url))
  if (req.nextUrl.pathname === '/old-blog')
    return NextResponse.rewrite(new URL('/blog', req.url))
  return NextResponse.next()
}
export const config = { matcher: ['/((?!api|_next).*)'] }

    

    

    
Pick a URL.

    

      
Remember from this chapter

      
  • Middleware runs before routing finishes — keep it fast and small.
  • Use config.matcher so it skips assets and API paths.
  • Redirect changes the URL; rewrite keeps the URL but serves another page. Newer Next.js versions rename this file convention to proxy — check your version.

    

  


  
  

    
Bonus 2

    
Server Actions

    
Submit a form and run a function on the server — no hand-written API route.

    
📮Like a mail slot: You drop a note in the slot (form). A worker inside reads it, updates the library, then hands back a fresh page.

    
async function addTodo(formData) {
  'use server'
  await db.todos.create({ title: formData.get('title') })
  revalidatePath('/todos')
}

    
    

    
Press submit to follow the request.

    

      
Remember from this chapter

      
  • A Server Action is a public POST endpoint — always validate input and check auth inside it.
  • revalidatePath / revalidateTag tell Next.js which cached data is now stale.
  • Forms can work before hydration — progressive enhancement.

    

  


  
  

    
Bonus 3

    
Streaming & Suspense

    
Send the page in pieces so slow parts never block fast parts.

    
🚰Like a restaurant: Bring bread right away; the main dish arrives when it is ready. Each <Suspense> is a covered plate.

    
<Header />
<Suspense fallback={<Skeleton />}><Reviews /></Suspense>
<Suspense fallback={<Skeleton />}><Recommendations /></Suspense>

    
    
    
    
    
    

      
Shell + Header (streaming)—

      
Reviews—

      
Recommendations—

      
Without streaming the user would see nothing until the slowest part finishes.

    

    

      
Remember from this chapter

      
  • Streaming improves perceived speed: users see the shell immediately.
  • loading.tsx is automatic Suspense around a whole route segment.
  • Put Suspense close to the slow data, not around the whole page.

    

  


  
  

    
Bonus 4

    
Rendering Strategies

    
SSG, SSR, ISR, PPR — pick by who sees the page and how often it changes.

    
🍳Like a bakery: Pre-baked bread (SSG), baked on order (SSR), pre-baked but refreshed every hour (ISR), or fresh toppings on a ready base (PPR).

    

      
      
    

    

    

      
SSG
HTML built at next build. Fastest, CDN friendly.

      
SSR
HTML built per request. Fresh and personal, costs server time.

      
ISR
Static page re-generated after revalidate time or on demand.

      
PPR
Static shell plus streamed dynamic holes. Availability depends on version.

    

    

      
Remember from this chapter

      
  • Using cookies, headers or uncached data makes a route dynamic automatically.
  • Static is cheaper and faster; dynamic is fresher and personal.
  • You choose per route, not per app.

    

  


  
  

    
Bonus 5

    
Node vs Edge Runtime

    
Where your server code runs decides which tools it can use.

    
🌍Like two kitchens: A big kitchen (Node) has every appliance but is far away. A tiny food truck (Edge) is close to you and starts instantly, but carries fewer tools.

    

    

    
export const runtime = 'edge' // or 'nodejs'

    

      
Remember from this chapter

      
  • Edge = fast cold start, low latency, limited Node APIs.
  • Native modules, fs and many DB drivers need the Node runtime.
  • Choose per route with export const runtime; default to Node unless you have a reason.
